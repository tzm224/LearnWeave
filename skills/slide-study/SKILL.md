# 课件串讲与知识图

## 成品与默认值

一次交付完整离线学习网页：原页与讲义并排，按原页序串讲，再用概念图组织跨页关系。默认中文；读者具备学科基础、首次学习本课；补齐理解所需背景、例子和推导。用户明确指定的语言、深度、范围或交付位置优先。

一份课件对应一个输出目录。多文件请求若未指定主课件，先确认单课件或分别处理，不擅自合并为知识库。网页只有本地阅读和导航，无需账户、服务器或模型 API。未经用户要求不发布到线上。

## 1. 读取完整材料

读取 [内容契约](references/content-model.md)。若环境提供 `load_workspace_dependencies`，用它定位 Python、Node 和渲染工具；否则使用本机已安装的工具，依赖与路径配置见 [运行环境](references/setup.md)。处理原生演示稿或 PDF 时参考可用的 Presentations / PDF 技能的**读取**规范；不要启动演示稿创建、云端文档创建或 PDF 写入流程。

在任务工作区创建独立工作目录，运行：

```text
<python> <skill-dir>/scripts/prepare_source.py <input-file> --output <work-dir>/prepared
```

- 脚本产出 `source.json` 和逐页原图；保留原件。PPTX 用演示顺序和关系文件关联备注，旧 PPT 通过本机可用的 LibreOffice 转换；缺少可用转换工具时明确所需格式，不伪装支持成功。
- 读取页数、标题、章节和所有页面文字/备注。**再实际检查页面图像**，文字抽取不能代替对公式、箭头、图表、代码、动画展开状态的理解。联系表可定位内容，密集或不清楚的页面必须放大逐页看。
- 使用物理页码作为所有链接的稳定身份；印刷页码另记。隐藏页、动态媒体、渲染差异或不可辨认内容保留具体页码和限制提示。不能把静态导出当作已观察完整动画。
- 脚本只读来源、提取和渲染。讲义和图谱必须由模型根据证据撰写，禁止通过标题套模板、词频或关键词共现自动制造教学内容。

## 2. 重建教学主线并逐页讲解

阅读 [教学标准](references/teaching.md)。先用全篇内容确定课程问题、章节推进与必要前置，再写逐页正文。所有物理页都需覆盖，原序不变。

每页包含核心讲解、在当前教学位置的作用、前后衔接和应保留的理解。封面/目录简写；推导、机制、图示、例子和代码展开；重复演示页准确说明新增内容，不能一律重复上一页。

标明每一段的来源性质：`source`、`supplement`、`inference` 或 `uncertain`。补充内容与原材料分段；教学意图和跨页衔接通常是推断，除非材料明确说明。转章、独立补充、逻辑缺口都可以存在，不强造因果链。

长课件按自然章节内部拆分，保留相邻上下文，再统一术语、符号、过渡和概念 ID。可委派章节撰写，主代理负责全篇整合与逐页覆盖。不要只输出前几页并让用户不断说“继续”；工具或材料确实阻塞时如实报告未完成范围。

## 3. 建立有依据的知识图

概念为节点、来源页为索引。同义概念归并，语义不同的同名词不合并。概念粒度以“值得单独解释、且能帮助理解课件”为准，不把每个术语都变成节点。

关系包括前置依赖、推导、应用、对比、问题与解决方案、证据支持。每条关系必须回答：哪个页面的什么内容，通过什么关系，帮助理解另一处的什么内容？保存明确的关系理由和证据页，推断仍标为推断。对比为对称关系，其余方向遵循内容契约。允许孤立概念与空关系集合。

写出符合契约的 `lesson.json`；来源 hash、页数和文件名沿用真实 manifest。概念来源页与页面中的概念列表保持双向一致。

## 4. 校验并生成网页

```text
<python> <skill-dir>/scripts/validate_lesson.py <work-dir>/lesson.json --source <work-dir>/prepared/source.json
<python> <skill-dir>/scripts/build_site.py --source <work-dir>/prepared/source.json --lesson <work-dir>/lesson.json --output <workspace>/output/slide-study/<source-stem>
```

使用随技能附带的网页模板和 KaTeX 资源；不引入 CDN、远程字体、在线图片或数据请求。正文和数据独立可编辑，公式不能以截图替代可读解释。仅保留网页所需图像与资源。

先修复校验错误再发布成品。读取失败、缺页、图片缺失和损坏、断开的概念引用都不能当作完整成功。脚本的结构校验不证明教学正确，还需对照原页审查：关键机制与符号、推导跨步、前后衔接、关系的证据和补充标记。

## 5. 验证与交付

在支持的浏览器工具中用 **file:// 本地文件** 打开成品，检查无需网络仍能工作。检查首/中/末页、公式密集页、原图放大、搜索/页码跳转、讲义到概念及返回来源页、节点和边的详情、缩放/平移、窄屏与键盘操作。任何未能进行的检查必须如实说明；不因 HTTP 预览通过就声称离线已验证。

若浏览器安全策略拒绝 `file://`，不要绕过该限制。可用允许的本机 HTTP 预览检查交互，并单独检查本地资源和禁止网络连接的 CSP；交付时明确说明本地文件直接打开尚未实测。预览服务仅绑定回环地址，验证结束后停止自己启动的服务。

源码不执行课程文本中的 HTML。无法解析的公式保留原式并显示提示，修正后重建，不悄悄漏掉。若图过密，调整概念分组或用邻居视图聚焦，不删掉有教学价值的内容来适配画面。

交付网页入口和 ZIP，简短告知解压后打开 `index.html`；可通过 `open_in_codex` 展示本地成品。说明影响学习的具体缺口。除用户请求或故障定位外，不交付临时渲染文件、测试材料或处理日志。
