# 质量评审与验收

结构校验通过，只能说明产物自洽。是否解释了设计逻辑，仍须回到原材料判断。

## 结构检查

运行 `python3 <skill-dir>/scripts/validate.py <output-dir>`，修复返回的错误。检查覆盖声明、来源与节点引用、主线顺序、分层视图、关系方向及 Mermaid 一致性。来源 URL/路径能够重开、定位确实指向所述内容，需要另行核对；ID 存在不等于证据有效。

确认八份交付文件齐全，Markdown 中没有模板占位值；overview 的导航可打开，节点深入链接指向对应内容。修改 JSON 后重新生成 Mermaid。校验工具不负责判断事实、证据强度或作者意图。

## 内容检查

围绕核心贡献选择一条重要设计链，逐项核对：

1. **问题**：能否说出为什么需要这篇材料，以及作者实际针对的限制？
2. **Idea**：是否解释了认识或解决方向上的变化，而非重复方法名称？
3. **架构**：沿一个输入或论证，能否走通组件/阶段间的交互？
4. **决策**：是否解释选择与约束的联系？未报告的动机或替代方案是否明确标为推断/未知？
5. **机制与证据**：哪些结果是作者主张，哪些有直接支持，哪些只是合理解释？支持关系有无超出实验或证明范围？
6. **权衡**：同时呈现获得与代价，区分原文结论和未验证的推测；保留适用条件。
7. **迁移**：pattern 是否有具体结构、适用条件和失效边界，而非“提高效率”一类口号？

再抽查一条跨章节关系、一条 AI 推断和一个 L3 证据节点。材料不存在其中某类时不强行补造。核对数字、符号、比较基线和范围；高 confidence 不得用来掩盖缺少证据。

## 主线与图谱检查

- 主线的下一步回答前一步留下的问题，而不是依次复述章节标题。
- Graph 的边具有具体理由和正确方向；`depends_on` 从依赖方指向前提，`supports` 从证据指向主张。
- 原文明确的节点之间，AI 推断的关系仍标为 `ai_inference`。对称比较不表现为因果方向。
- L1 可快速理解整篇，L2 解释设计机制，L3 承载细节。必要的高价值微观节点没有因为画面拥挤而消失。
- `importance`、`learning_depth` 与 `level` 有各自理由；不把所有核心节点都机械设为详细学习。

## 独立使用检查

当材料复杂或修改了关键流程时，可让独立评审者只拿技能、原始材料和产物，回答：问题、核心 Idea、整体组织、关键选择理由、相对已有方案的变化、迁移思想与逻辑关系。评审者须能指出原文依据及哪些回答尚不确定。

优先修复错误因果、虚构动机、证据错配、关键机制遗漏和来源断链。不要用固定措辞测试替代上述判断，也不要为统一文风不断扩充正文。合成示例只能证明示例上的行为；没有真正测试未见论文，就不能声称已通过该项验收。

## 维护技能时的回归检查

修改 Schema、绘图或校验脚本后执行：

```text
python3 -B -m unittest discover -s <skill-dir>/scripts/tests -v
python3 -B <skill-dir>/scripts/validate.py <skill-dir>/examples/versioned-cache/expected
python3 -B <skill-dir>/scripts/validate.py <skill-dir>/examples/mergeable-summary/expected
```

这些测试覆盖不完整产物、错误引用、缺少归属、证据/模式边界字段、关系方向、包含环、累积视图、主线一致性、节点深入链接和图谱转义。测试不运行示例中的缓存协议，也不证明它有性能优势。

正式 Schema 使用 Draft 2020-12；为避免运行依赖，随附检查器仅实现这些 Schema 实际用到的关键字，并对遇到的不支持关键字报错。它不是通用 JSON Schema 验证库。新增 Schema 关键字时应同步扩展检查器和测试，或显式选择环境中已有的标准验证器，不能静默忽略断言。

更改教学流程时，用一份没有提供预期答案的新材料试用。验收除了能生成八文件，还需核对材料是否被准确重建；系统型与理论型材料应呈现各自真实的组织形式。独立试用不可用时如实记录，结构测试不能替代它。
